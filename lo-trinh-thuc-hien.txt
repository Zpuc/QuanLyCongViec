LỘ TRÌNH XÂY DỰNG DỰ ÁN QUẢN LÝ CÔNG VIỆC (TASK MANAGEMENT SYSTEM)
Tech Stack: React (Vite + TypeScript) | NestJS | PostgreSQL + Prisma ORM
Tiêu chuẩn: Đồ án chuyên ngành / Khóa luận tốt nghiệp Sinh viên năm 4
================================================================================

--------------------------------------------------------------------------------
GIAI ĐOẠN 1: KHẢO SÁT, PHÂN TÍCH & THIẾT KẾ HỆ THỐNG (Tuần 1 - 2)
--------------------------------------------------------------------------------
Mục tiêu: Có đầy đủ bản vẽ và tài liệu thiết kế trước khi bắt tay vào viết code.

1. Xác định Tác nhân (Actors) & Phân quyền:
   - Quản trị viên hệ thống (System Admin): Quản lý người dùng, thống kê chung.
   - Chủ dự án (Project Owner / Manager): Tạo dự án, mời thành viên, phân quyền,
     tạo cột trạng thái, giao việc, xóa dự án.
   - Thành viên (Member): Xem bảng công việc, cập nhật trạng thái task được giao,
     bình luận, tải lên tệp đính kèm.
   - Người xem (Viewer - Tùy chọn): Chỉ xem tiến độ, không được chỉnh sửa.

2. Danh sách chức năng cốt lõi (Use Cases):
   - [Auth] Đăng ký, Đăng nhập (Access Token + Refresh Token), Đổi/Quên mật khẩu.
   - [User] Quản lý thông tin cá nhân, đổi ảnh đại diện (Avatar).
   - [Workspace/Project] CRUD dự án, thêm/xóa thành viên qua Email, gán vai trò.
   - [Kanban Board] Quản lý cột trạng thái (TODO, IN_PROGRESS, REVIEW, DONE).
   - [Task] CRUD công việc, kéo thả (Drag & Drop) đổi trạng thái/thứ tự, gắn nhãn
     (Labels), độ ưu tiên (Low/Medium/High/Urgent), hạn chót (Due Date), người
     thực hiện (Assignee).
   - [Collaboration] Bình luận vào công việc, đính kèm file/ảnh, lịch sử hoạt động
     (Activity Log - ai vừa đổi trạng thái gì).
   - [Notification] Thông báo thời gian thực (Real-time với Socket.io) khi được
     giao việc hoặc có người bình luận.
   - [Dashboard] Thống kê số lượng công việc hoàn thành, quá hạn, biểu đồ tiến độ.

3. Thiết kế Cơ sở dữ liệu PostgreSQL (ERD):
   * Tận dụng thế mạnh của PostgreSQL: dùng kiểu `UUID` cho khóa chính, kiểu `ENUM`
     cho trạng thái/quyền hạn, `TIMESTAMPTZ` cho thời gian, và `JSONB` để lưu chi
     tiết lịch sử thay đổi (Activity Log).
   - ENUMs:
     + `project_role`: 'OWNER', 'ADMIN', 'MEMBER', 'VIEWER'
     + `task_priority`: 'LOW', 'MEDIUM', 'HIGH', 'URGENT'
   - Bảng `users`: id (UUID), email (UNIQUE), password_hash, full_name, avatar_url,
     is_active, created_at, updated_at.
   - Bảng `projects`: id (UUID), name, key (VD: PROJ - UNIQUE), description,
     owner_id (FK -> users.id), created_at, updated_at.
   - Bảng `project_members`: id (UUID), project_id (FK), user_id (FK),
     role (project_role), joined_at. (UNIQUE constraint trên cặp project_id + user_id).
   - Bảng `board_columns`: id (UUID), project_id (FK), title, position_order (FLOAT/INT),
     created_at.
   - Bảng `tasks`: id (UUID), project_id (FK), column_id (FK), task_number (INT),
     title, description (TEXT), priority (task_priority), position_order (FLOAT),
     assignee_id (FK -> users.id), reporter_id (FK -> users.id), due_date (TIMESTAMPTZ),
     created_at, updated_at.
   - Bảng `task_comments`: id (UUID), task_id (FK), user_id (FK), content (TEXT),
     created_at, updated_at.
   - Bảng `task_attachments`: id (UUID), task_id (FK), file_name, file_url,
     file_size, mime_type, uploaded_by (FK), created_at.
   - Bảng `notifications`: id (UUID), recipient_id (FK), title, content,
     type, is_read (BOOLEAN), metadata (JSONB), created_at.
   - Bảng `activity_logs`: id (UUID), project_id (FK), task_id (FK), user_id (FK),
     action, old_value (JSONB), new_value (JSONB), created_at.

GIAI ĐOẠN 2: DỰNG BASE PROJECT & CẤU HÌNH HẠ TẦNG (Tuần 3)
--------------------------------------------------------------------------------
Mục tiêu: Khởi tạo khung dự án chuẩn chỉnh, dễ mở rộng, có sẵn công cụ kiểm thử.

1. Hạ tầng & Quản lý mã nguồn:
   - Khởi tạo Git repository, tạo file `.gitignore`, chia nhánh `main` và `develop`.
   - Tạo Database trống trên PostgreSQL máy local (ví dụ: `task_management_db`)
     thông qua pgAdmin 4 hoặc `psql`.

2. Dựng Base Backend (NestJS + PostgreSQL + Prisma):
   - Khởi tạo project NestJS (`backend`), cấu hình biến môi trường (`.env`) với
     `@nestjs/config` và chuỗi kết nối `DATABASE_URL="postgresql://postgres:password@localhost:5432/task_management_db?schema=public"`.
   - Cài đặt Prisma (`prisma`, `@prisma/client`), chạy `npx prisma init`.
   - Thiết kế toàn bộ bảng, ENUM, quan hệ và Index trong `prisma/schema.prisma`.
   - Chạy `npx prisma migrate dev --name init_db` để tự động tạo bảng vào PostgreSQL.
   - Tạo `PrismaModule` (`@Global()`) và `PrismaService` để tái sử dụng trong toàn
     bộ các module của NestJS.
   - Sử dụng `npx prisma studio` để quản lý/xem dữ liệu trực quan ngay trên trình duyệt.
   - Thiết lập `ValidationPipe` toàn cục (`class-validator`, `class-transformer`).
   - Thiết lập `TransformInterceptor` (chuẩn hóa JSON trả về: `{ statusCode, message, data }`).
   - Thiết lập `HttpExceptionFilter` (chuẩn hóa cấu trúc báo lỗi).
   - Tích hợp Swagger (`@nestjs/swagger`) tại `/api/docs` để tài liệu hóa API.
   - Cấu hình CORS để Frontend gọi được API.

3. Dựng Base Frontend (React + Vite + TypeScript):
   - Khởi tạo project React + TypeScript bằng Vite.
   - Cài đặt thư viện UI (Ant Design hoặc Shadcn UI + TailwindCSS).
   - Cấu hình `axiosClient` (Interceptors tự động đính kèm Access Token và tự động
     gọi Refresh Token khi hết hạn 401).
   - Cấu hình `TanStack React Query` (quản lý gọi API, caching, loading state).
   - Cấu hình `Zustand` (lưu trữ trạng thái đăng nhập của User).
   - Thiết lập `React Router` với `ProtectedRoute` (chặn người dùng chưa đăng nhập)
     và chia Layout (`AuthLayout`, `MainLayout` có Sidebar + Header).

--------------------------------------------------------------------------------
GIAI ĐOẠN 3: PHÁT TRIỂN CÁC MODULE CỐT LÕI - MVP (Tuần 4 - 6)
--------------------------------------------------------------------------------
Mục tiêu: Hoàn thành luồng nghiệp vụ chính từ đăng nhập đến quản lý công việc.

1. Module Xác thực & Người dùng (Auth & Users):
   - Backend: API Register, Login, Refresh Token, Get Profile (`GET /auth/me`),
     Update Profile, `JwtAuthGuard`.
   - Frontend: Trang Đăng nhập, Đăng ký, Trang thông tin cá nhân, xử lý lưu Token.

2. Module Dự án & Phân quyền (Projects & Members):
   - Backend: API CRUD Project, mời thành viên vào dự án, Custom Guard kiểm tra
     quyền trong dự án (`ProjectRoleGuard` - chỉ Owner/Admin mới được xóa/sửa dự án).
   - Frontend: Trang danh sách dự án, Modal tạo dự án mới, trang Quản lý thành viên.

3. Module Bảng công việc & Kéo thả (Kanban Board & Tasks):
   - Backend: API tạo/sửa/xóa cột, API tạo/sửa/xóa Task, API cập nhật vị trí
     (`PATCH /tasks/:id/move`) khi người dùng kéo thả task sang cột khác hoặc đổi
     thứ tự trong cùng cột, bộ lọc công việc (theo người làm, độ ưu tiên, từ khóa).
   - Frontend: Giao diện bảng Kanban (sử dụng `@hello-pangea/dnd` hoặc `@dnd-kit`),
     Modal xem/chỉnh sửa chi tiết Task, thanh tìm kiếm và bộ lọc trên Board.

--------------------------------------------------------------------------------
GIAI ĐOẠN 4: TÍNH NĂNG NÂNG CAO - "ĂN ĐIỂM" ĐỒ ÁN NĂM 4 (Tuần 7 - 8)
--------------------------------------------------------------------------------
Mục tiêu: Tạo sự khác biệt với các đồ án CRUD thông thường.

1. Bình luận & Đính kèm tệp (Comments & Attachments):
   - Upload ảnh/tài liệu (lưu local hoặc Cloudinary / AWS S3).
   - Bình luận trực tiếp trong từng Task.

2. Lịch sử hoạt động (Activity Audit Log):
   - Tự động ghi nhận lịch sử: "Nguyễn Văn A đã chuyển task X từ TODO sang DONE".

3. Thông báo thời gian thực (Real-time Notifications):
   - Tích hợp `@nestjs/websockets` (Socket.io) ở Backend và `socket.io-client` ở Frontend.
   - Hiển thị biểu tượng chuông thông báo nảy số ngay lập tức khi được giao task.

4. Dashboard & Báo cáo thống kê:
   - API thống kê tổng số task theo trạng thái, theo thành viên, số task trễ hạn.
   - Frontend vẽ biểu đồ trực quan (dùng `Recharts` hoặc `Chart.js`).

--------------------------------------------------------------------------------
GIAI ĐOẠN 5: KIỂM THỬ, SEED DATA & CHUẨN BỊ BẢO VỆ (Tuần 9 - 10)
--------------------------------------------------------------------------------
Mục tiêu: Đảm bảo hệ thống chạy mượt mà, có dữ liệu đẹp để trình bày trước hội đồng.

1. Viết Script Seed Data (`npm run seed`):
   - Tự động tạo sẵn 3-5 tài khoản mẫu (Admin, Leader, Member).
   - Tạo sẵn 2 dự án thực tế (VD: "Phát triển Website Thương mại điện tử") với
     đầy đủ các cột và khoảng 15-20 công việc, bình luận để biểu đồ Dashboard hiển
     thị đẹp mắt khi bảo vệ.

2. Kiểm thử & Tối ưu:
   - Viết Unit Test cơ bản cho các Service quan trọng ở Backend (Auth, Task).
   - Kiểm tra lỗi giao diện (Loading skeleton, thông báo Toast khi thành công/thất bại,
     Responsive cơ bản).

3. Hoàn thiện Tài liệu & Slide báo cáo:
   - Viết `README.md` hướng dẫn cài đặt và chạy dự án chi tiết.
   - Xuất sơ đồ Use Case, ERD, Sequence Diagram (cho luồng Login, Kéo thả Task)
     đưa vào quyển báo cáo.
